# Профиль настоящего tailsitter из 1.0.0.param

Подготовлен отдельный профиль для CubeOrangePlus:
[DualMotorCubeOrangePlus.parm](../Tools/Frame_params/Tailsitters/DualMotorCubeOrangePlus.parm).
Это перенос настроек в имена и единицы текущего кода ArduTailSitter V4.7.1.
Четыре изменения штатных настроек согласованы пользователем 28 октября
2026 года и применены. Ниже перечислены оставшиеся ограничения проверки.

Исходный `1.0.0.param` оставлен без изменений. SHA-256:
`b68c42771e370bd27704b83928d2ee20ff7afa20117dc312b42275f545045137`.
Неудачная ветка не используется как источник алгоритмов. Неизвестные
параметры не добавлялись в текущую прошивку.

## Какие параметры удалены

У следующих 16 имён нет действующего объявления или установленного аналога
в текущем коде. Их предполагаемая логика не восстанавливалась:

```text
Q_DES_HEIGHT        Q_DESC_THR
Q_M_THR_HV_MAX      Q_P_PITCH_MAX      Q_P_ROLL_MAX
Q_POS2_SPD          Q_POS2_THR
Q_RLX_ABRAKE        Q_RLX_POS1
Q_SKIP_STAGES       Q_TR_OPTIONS
Q_TAILSIT_P_END     Q_TAILSIT_P_ST     Q_TAILSIT_TR_ANG
Q_P_RELAX_TC       TECS_SNSPD_TM
```

Отдельно исключены устаревшие штатные имена:

- `FS_SHORT_TIMEOUT`: параметр удалён в этой версии; это отмечено
  в [ReleaseNotes](../ArduPlane/ReleaseNotes.txt).
- `CAM_RC_TYPE=0`: старый выбор RunCam; выключенный экземпляр не переносился
  в новую структуру камер.

Исходное `Q_P_RELAX_TC=0.16` совпадает со значением текущей постоянной
`POSCONTROL_RELAX_TC=0.16` в
[AC_PosControl.h](../libraries/AC_AttitudeControl/AC_PosControl.h).
Это совпадение не подтверждает происхождение старого параметра.

Также исключены `FORMAT_VERSION`, `MIS_TOTAL`, `FENCE_TOTAL`,
`STAT_BOOTCNT`, `STAT_FLTTIME`, `STAT_RUNTIME`, `STAT_RESET`.
Число точек миссии или геозоны само по себе не переносит их содержимое.
Настоящих калибровок IMU и компасов в исходной выгрузке нет; этот профиль
не восстанавливает их калибровку на другом контроллере.

## Согласованные изменения

| Настройка | Применённое изменение |
| --- | --- |
| `Q_M_SPIN_ARM` | `0.30 → 0.10`, сохранив `Q_M_SPIN_MIN=0.25`. Устранено блокирующее сочетание SPIN_ARM > SPIN_MIN; реальную скорость холостого вращения нужно проверить на ESC |
| Старый `ARMING_CHECK=0` | Заменён явным `ARMING_SKIPCHK=0`: штатные предполётные проверки сохранены. Старую политику отключения проверок через `ARMING_SKIPCHK=-1` не переносили |
| `Q_TAILSIT_ENABLE` | `2 → 1`: обычный tailsitter с элевонами, без принудительного постоянного Qassist/airmode в горизонтальном полёте |
| `GPS_PRIMARY` | `4 → 0`: допустимый индекс. `GPS_AUTO_SWITCH=1` оставлен для автоматического выбора лучшего приёмника |

`GLIDE_SLOPE_MIN=0`, `GLIDE_SLOPE_THR=5` остаются отложенными: старые имена
не включены в профиль до подтверждения эквивалентности текущим `ALT_SLOPE_*`.
Значения текущих `ALT_SLOPE_*` отдельно не переопределялись.

Проверка сочетания SPIN_ARM/SPIN_MIN находится в
[AP_MotorsMulticopter.cpp](../libraries/AP_Motors/AP_MotorsMulticopter.cpp),
вызывается из [AP_Arming_Plane.cpp](../ArduPlane/AP_Arming_Plane.cpp).
Миграция старого ARMING_CHECK описана в
[AP_Arming.cpp](../libraries/AP_Arming/AP_Arming.cpp).
Поведение ENABLE=2 задано в [tailsitter.cpp](../ArduPlane/tailsitter.cpp).

Настройки батарейного failsafe, `FS_GCS_ENABL=0`, `FS_LONG_ACTN=0`,
`Q_RTL_MODE=0`, `BRD_SAFETY_DEFLT=0` и `FENCE_ENABLE=0` сохранены.
Удаление нестандартных параметров само по себе не включает аварийные
возврат и посадку, описанные в [сценариях отказов](tailsitter-failsafe.md).

## Результат проверки

28 октября 2026 года штатный генератор параметров
`Tools/autotest/param_metadata/param_parse.py --vehicle ArduPlane --format json --no-legacy-params`
успешно создал метаданные текущих исходников.

Проверены отсутствие повторяющихся имён, учёт всех 1402 исходных строк,
совпадение сохранённых значений, пересчёт перенесённых значений и ровно
четыре согласованных изменения.
Все эти проверки прошли. Исходный SHA-256 не изменился.

Имена профиля присутствуют в метаданных, кроме `FLTMODE_GCSBLOCK`, которое
явно объявлено для Plane в
[AP_Vehicle.cpp](../libraries/AP_Vehicle/AP_Vehicle.cpp), но пропущено
генератором документации. Оно сохранено и не отнесено к нестандартным.

Штатные функции `Tools/scripts/param_check.py` после четырёх изменений дали
41 замечание к значениям
по диапазонам и маскам. Они перечислены в
[таблице значений для проверки](tailsitter-1.0.0-value-review.csv).
Часть нулевых значений выключает соответствующие функции. Само замечание
к диапазону не устанавливает физическую неисправность или отказ ARM.
Значения не ограничивались автоматически и проверки не отключались.
В частности, оставлены для согласования `Q_TAILSIT_ANG_VT=85`,
`Q_TAILSIT_DSKLD=59`, `Q_LAND_FINAL_ALT=65` и настройки регуляторов,
выходящие за документированные диапазоны.

## Сборка профиля в прошивку

Из корня репозитория:

```sh
./waf configure --board CubeOrangePlus \
  --default-parameters="$PWD/Tools/Frame_params/Tailsitters/DualMotorCubeOrangePlus.parm"
./waf tailsitter
```

Абсолютный путь здесь нужен для выбора файла профиля обработчиком hwdef.
Эта опция выбирает профиль вместо штатного файла defaults платы. Все девять
параметров штатного файла CubeOrangePlus присутствуют в профиле;
из них реальные `BATT_AMP_PERVLT=24`, `BATT_VOLT_MULT=18`,
`SERIAL5_PROTOCOL=-1` отличаются от заводского файла и сохранены из выгрузки.
Исходный файл платы `CubeOrangePlus/defaults.parm` не менялся.

Файл для загрузки: `build/CubeOrangePlus/bin/ardutailsitter.apj`.
Компаньоны: `.bin`, `.abin`, `ardutailsitter_with_bl.hex`.
Предыдущая сборка сохранена в
`build/CubeOrangePlus/previous-stock-defaults-20261027/`.

Профиль встраивается как `@ROMFS/defaults.parm`. Проверяется не только
промежуточный `processed_defaults.parm`, но и точное сжатое содержимое
в декодированном образе APJ. Идентификатор платы остаётся 1063.

## Проверка распиновки в SITL

Для проверки реальных назначений добавлена отдельная модель
`plane-tailsitter-dual-real`. Её двигатели получают сигналы выходов 1/2,
левый элевон — среднее выходов 5/6 с обратным знаком механической передачи,
правый — среднее 7/8. Выходы RCIN10 3/4 не создают тягу или управляющие
моменты. Это та же условная аэродинамика прежней модели, с другой проводкой.
Прежняя `plane-tailsitter-dual` сохраняет выходы и тестовые коэффициенты.

```sh
./waf configure --board sitl
./waf tailsitter
./waf --targets tests/test_sim_plane_tailsitter_dual
build/sitl/tests/test_sim_plane_tailsitter_dual
Tools/autotest/autotest.py --speedup=20 test.QuadPlane.TailsitterRealProfileSetup
```

`TailsitterRealProfileSetup` загружает полный реальный профиль напрямую,
сравнивает доступные runtime-параметры и проверяет назначения и микшер
элевонов, дублирование каналов, RCIN10 и отсутствие тяги двигателей
при переходах MANUAL → QHOVER → MANUAL. На всём тесте аппарат остаётся
DISARMED. Отсутствующие в SITL аппаратные параметры перечисляются отдельно;
ключевые настройки проверяются обязательными утверждениями.

В тесте отдельно задаётся только настройка симулятора `SIM_IMU_COUNT=3`,
чтобы число IMU соответствовало трём включённым IMU CubeOrangePlus.
Реальные настройки датчиков, калибровок и arming-проверок не подменяются.
Тестовый стенд запрашивает телеметрию с частотой 10 Гц и изменяет девять
`MAV1_*` значений; они проверяются отдельно от неизменённых значений профиля.

Тесты физической модели проверяют маски и RPM двух двигателей, эквивалентность
сил и моментов прежней модели при правильном переназначении, усреднение
дублированных элевонов и отсутствие влияния RCIN10 на физику.

28 октября 2026 года успешно прошли:

- Сборки SITL и CubeOrangePlus.
- Все девять тестов `test_sim_plane_tailsitter_dual`, включая пять прежних.
- `TailsitterRealProfileSetup`: 1325 неизменённых runtime-значений профиля,
  девять частот, управляемых стендом, 41 недоступное в SITL аппаратное имя;
  всего учтены все 1375 настроек.
- `TailsitterAutoMission` и `TailsitterDualMotorSetup` для прежней условной
  модели: сохранена работа AUTO и её исходной распиновки.
- `py_compile`, `flake8`, `git diff --check` и проверки таблицы переноса.

Прошивка содержит 23611 байт точного текста профиля в сжатом ROMFS-файле.
SHA-256 профиля:
`0f78c25ea4b0fa11db76efc416abb2e6d4d7f1dfbe6bd4a1114088ebe541403f`.
Проверены board ID 1063, совпадение декодированного APJ с BIN и тела ABIN
с BIN. Образ занимает 1715872 байта при доступных 1966080;
остаётся 250208 байт.

Текстовые журналы, список аппаратных имён, недоступных в SITL, и JSON-отчёт
сохранены в `build/sitl/tailsitter-real-profile-validation/`.
В `build/CubeOrangePlus/bin/` также находятся `SHA256SUMS`,
`firmware-build-info.json` и CSV-копия профиля `ardutailsitter.param`
для отдельного импорта параметров.

Эти проверки не подтверждают лётную настройку настоящего аппарата.
Полный реальный профиль в воздухе не испытывался; геометрия, масса,
силовая установка и аэродинамика самолёта не определяются выгрузкой параметров.
Алгоритмы управления и аварийных действий прошивки не менялись.

При встраивании defaults через сборку уже сохранённые параметры
контроллера имеют приоритет. Прошивка с новыми defaults не должна считаться
подтверждением применения профиля к существующему Cube. Сброс параметров
и перезапись калибровок не выполнялись.

При необходимости применить профиль на уже настроенном Cube требуется
отдельно загрузить его параметры и проверить прочитанные обратно значения.
Одна загрузка `.apj` не подтверждает, что четыре согласованные настройки
заменили ранее сохранённые значения. Аппаратная прошивка и параметры
на подключённый контроллер автоматически не загружались.

Профиль, таблицы и анализ подготовлены с помощью AI.
